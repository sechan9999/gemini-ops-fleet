# Agent Spec — Gemini Ops Fleet

**Hackathon:** All Things Agentic Hackathon (Devpost / Google Cloud)
**Track:** The Fortified Enterprise Fleet
**Submission deadline:** 2026-08-31 17:00 PT

## Overview

A fleet of governed back-office agents for a ~50-person manufacturing/sales company that has no IT
department. A single `Activity` event stream feeds every agent; agents react to events
asynchronously rather than waiting on a chat prompt.

The thesis is inverted from the usual agent demo: the interesting part is not how much the agents do
on their own, but what they are structurally prevented from doing. Role-scoped retrieval, inline
guardrails, and a human approval gate are the product, not the safety disclaimer.

## Agents

| Agent | Trigger | Does | Must not |
|-------|---------|------|----------|
| Triage | `as.opened` | Classify category + severity, assign to least-loaded owner | Modify the original ticket text |
| Knowledge | `as.resolved` | Turn the resolution into a structured knowledge item, index it for retrieval | Publish outside the owning department's scope |
| Follow-up | `delivery.done` | Draft a customer message | **Send anything** — draft only, human approves |
| Reconcile | `transaction.posted` | Match orders against accounting entries, report integrity rate and mismatches | Post or alter financial records |

Agents coordinate over the A2A protocol and are published to a registry so other departments can
discover them by capability.

## Example Use Cases

1. A support ticket arrives at 02:00. Triage classifies it and assigns an owner. No human is online;
   the work happens off the event stream. In the morning the owner sees it already routed.
2. The owner resolves the ticket. Knowledge captures the resolution and indexes it. A week later a
   different employee's search surfaces that resolution as grounded context with a citation.
3. A delivery completes. Follow-up drafts a customer message and parks it in an approval queue. It
   stays there until a human approves. Nothing is sent otherwise.
4. A sales rep searches for "our refund policy" and gets the customer-facing policy. The same query
   from the same rep does **not** return the internal accounting reconciliation memo — that document
   is scoped to finance. The failure is the demo.

## Tools Required

| Tool | Purpose | Auth |
|------|---------|------|
| `search_knowledge` | Retrieval over the knowledge base, filtered by caller role | Internal, role from verified identity |
| `get_customer_360` | Aggregate customer view | Internal, row-level scoped to owner |
| `list_open_tickets` | Ticket queue for the caller's scope | Internal |
| `get_pipeline` / `get_inventory` | Derived operational views | Internal |
| `reconcile_accounting` | Order↔ledger integrity check | Internal, finance role only |
| `triage_ticket` | Classify and assign | Internal |

No tool sends external communications or moves money. Outbound customer messages go through a
separate human-approved path.

## Constraints & Safety Rules

1. **No unapproved outbound.** The follow-up agent produces drafts. Sending requires an explicit
   human approval action. There is no code path where an agent sends a customer message on its own.
2. **Role-scoped retrieval.** Every retrieval call is filtered by the caller's verified role before
   results are returned — not filtered in the prompt, filtered in the query. A sales role cannot
   retrieve finance documents.
3. **Identity is server-derived.** Role comes from the authenticated principal, never from a
   caller-supplied parameter or from anything the model produces.
4. **No silent edits.** Agents never rewrite source records. They append derived artifacts.
5. **Guardrails inline.** Prompt injection attempts and PII in model output are blocked at the
   gateway, before the response reaches a caller or a tool.
6. **Everything is traced.** Each agent decision emits an OpenTelemetry span; the reasoning chain is
   reconstructable from traces.

## Success Criteria

| Criterion | Measure |
|-----------|---------|
| Async execution | An event triggers a complete agent chain with zero human interaction |
| Cross-session memory | Context from a prior session is recalled after restart |
| Access control | A sales-role query for a finance document returns nothing — demonstrated live |
| Guardrail | An injection attempt is blocked and logged |
| Human gate | Zero customer messages sent without recorded approval |
| Discovery | Agents are listed in the registry with version and capability metadata |
| Observability | A full reasoning chain is readable in Cloud Trace |

## Architecture

- **Model:** Gemini via Vertex AI, behind a single gateway module (one choke point for routing,
  policy, and guardrails)
- **Framework:** Google ADK, A2A protocol between agents
- **Runtime:** Cloud Run, driven by Pub/Sub events
- **State:** Cloud SQL (Postgres) + pgvector for retrieval, self-managed so that access control runs
  in SQL rather than in the prompt
- **Memory:** ADK Memory Bank for cross-session context
- **Guardrails:** Model Armor, inline at the gateway
- **Telemetry:** OpenTelemetry → Cloud Trace

### Scaffold decisions

| Choice | Value | Note |
|--------|-------|------|
| Template | `adk_a2a` | A2A between fleet members |
| Deployment target | `cloud_run` | scale-to-zero for cost |
| Region | `us-central1` | |
| Session type | requested `cloud_sql`, scaffold applied `in_memory` | **Open item** — the A2A template does not accept a session type. Persistence must be wired manually or via `scaffold enhance` before the fleet can claim long-lived state. |
| CI/CD | deferred (`--prototype`) | Add with `scaffold enhance --cicd-runner` if time allows |
| Datastore | none (self-managed pgvector) | Managed datastores make row-level access proof harder |
